# Four-stream standard QSA helper regression (V83)

Date: 2026-10-16. This is a bounded operator fixture only: physical GPU3, four independent Q8_0 streams, no model weights, no engine service, and no dense F16 FlashAttention reference.

## Shape and comparison

- 4 streams × 4 query tokens per stream (16 flattened tokens), tested with 4 and 8 query heads; K/V uses one KV head (GQA4 and GQA8).
- Q8_0 K/V backing capacity is 16384 cells per stream; the active view is 8192 cells. The 8192-cell inactive tail is filled with canary data and read back after graph compute.
- 2051 selected cell IDs are padded to 2052. Query rows, mask/ID token rows, and per-stream cache intervals retain non-tight strides.
- Each of the two input seeds changes Q, K, V, mask, and IDs. Each stream has independent contents and mask visibility.
- The graph compares `llama_qsa_standard_sparse::build()` against four separate original explicit-cell `FLASH_ATTN_EXT` consumers. For both seeds and both head counts, helper and explicit outputs are bitwise identical; outputs are finite and the canaries remain unchanged.
- Seed 0 also passes the Q8_0 FP64 oracle over all 16 query tokens and all heads. CPU selected-order versus dense masked FP64 differs by at most `3.09e-14`.

| Query heads | Helper versus four explicit consumers | FP64 max absolute error | Finite values | Changed-seed output | Tail canaries |
|---:|---|---:|---|---|---|
| 4 | bitwise exact | `6.98e-7` | all | changed | intact |
| 8 | bitwise exact | `7.38e-7` | all | changed | intact |

FP64 tolerance was fixed at `atol=2e-6`, `rtol=2e-5`. The direct helper and old explicit consumer use the same actual Q8_0 cache bytes. The fixture does not build or run the separate dense F16 FlashAttention path.
